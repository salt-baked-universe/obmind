## 1.9.1 快捷键面板被画布遮住

- 现象：点「?」弹出的操作与快捷键面板，下半部分被 `.obmind-canvas` 盖住。
- 根因是**层叠上下文**，不是 z-index 数值太小：
  1. `.obmind-toolbars` 带 `container-type: inline-size`，而 layout containment
     会建立新的层叠上下文 —— 面板自身的 `z-index: 30` 被困在这个上下文里，
     跟外层的画布根本没有可比性（探针实测：给 toolbars 加 `z-index:-1` 后
     面板立刻被面包屑/画布盖住，证明它确实被困在内部）。
  2. 画布是 `position: relative` 的兄弟节点，在文档里排在 header 之后。
  → 给面板调 z-index 没用（1.8.0 就是只写了个 30）。
- 修法：`.obmind-header { position: relative; z-index: 100 }` 整块 UI 层抬起来，
  `.obmind-canvas { z-index: 0 }` 把内容层显式压下去（防主题给内容区抬层）。
  100 既压得住画布，又不会盖到 Obsidian 的模态（1000）/菜单（1500）。
- 顺带给面板加 `max-height: min(60vh, 420px); overflow-y: auto` ——
  `.view-content` 是 overflow: hidden，窄窗口下 11 行会顶出底边被裁掉。
- 验证：直接 link 真实 `styles.css` 起探针页（不手抄 CSS），
  窗口 1200×900 与 1200×520 两档，面板内 5 个采样点 `elementFromPoint`
  全部命中面板，可见高度 = 完整高度。
- 教训：**凡是在 `container-type` 容器里做浮层，都要重新审视 z-index**，
  它不再是全局序号，而是该容器上下文内的序号。

## 1.10.0 分支配色不再跳色 + 操作栏重做

- **跳色的根因是「颜色按位置分配」**：markmap 的 `state.path` 是位置编码
  （"0.2.1" 里的 2 是兄弟序号），原来直接 `colors[path.split(".")[1] % 6]`，
  所以文件里插一行 / 删一行，后面所有分支的颜色整体平移。XMind 不会，
  因为它的颜色是挂在分支自己身上的。
- 新增 `src/render/colors.ts`：`BranchColors` 粘性分配器。
  分支名归一化后当 key（去 `**`、`` ` ``、链接地址、HTML 标签），
  已有 key 永远保留槽位 —— 增删只影响新出现的那根；
  「一增一减」时槽位直接过户，所以**改名也不换色**；
  冷启动按哈希排序分配（与文档顺序无关），重开视图结果基本一致。
  分支数 > 色板长度时才允许重复。28 项 Node 用例（插入/删除/改名/乱序/超长）。
- 色板 6 → 8 色：分支常态是 5～10 根，6 色一过必撞色，「两根分支同色」比
  「颜色不完美」难看得多。撞槽时向后探测空位，保证 ≤8 根时颜色各不相同。
- **「同色的二级节点」另有一个成因是浓淡**：原来 tint 0.1~0.13，二级节点混出
  近乎纯白，不同分支的浅底几乎一样。改成 0.24~0.34，并按层递减
  （`tintAt`，地板 35%）；非实色主题的一级节点浓度 `level1Tint = tint*1.5`
  （原来固定 0.18，和二级一样，层级感全靠字号）。
- 实色一级节点的文字色改 `readableOn`：白 / 深墨取对比度更高的那个。
  原来一律白字，在 #ff8a3d 上只有 2.35，字是糊的。全主题 40 色实测
  L1 ≥ 3.96、L2/L4 ≥ 4.6。
- 槽位解析做成**注入**（`NodePainter(slotOf)`），因为只有 View 手里有整棵树和
  跨重建保留的分配表；markmap 的 `color` 回调也在 render 里同步取色，
  所以 `syncBranchSlots()` 必须在 `setData` **之前**跑，path 只能从孩子顺序推。
- 操作栏重做：原生 `<select>`（92px，字号/高度/箭头都改不动）换成
  palette 图标按钮 + `Menu`（对勾表示当前项，手动选过主题时图标转强调色）。
  一行从 8 个控件 + 下拉 → 8 个 28px 图标，240px 侧栏也放得下。
  分隔线改 `currentColor + opacity .16`；删除单独成组；
  header 只留一条下边框（原来工具条一条 + 面包屑一条，横线比文字抢眼）。
- **换行问题**：240/260/300/360px 实测都没复现（旧版也已 `flex-wrap: nowrap`），

## 1.11.0 操作栏收成一行 + 节点浮动条 / 折叠动画重做

### 操作栏
- 两行的真正问题不是「挤」，是**第二行在没选中时是一排灰按钮**：长期占一行高度，
  却只有选中后才有意义；两排图标靠竖线分组，看着像两个工具条叠在一起。
- 改成：顶部**一行**只放全局操作（主题 / 撤销重做 / 折叠展开 / 适配 / 刷新 / 帮助），
  节点操作（子 / 同 / 改 / 提 / 删）搬到新增的 `src/ui/nodeBar.ts`，选中节点后
  浮在卡片正下方。操作跟着上下文走，还多出一行高度给画布。
- 定位是纯函数 `nodeBarPosition()`（贴底翻到上方 / 左右夹紧 / 卡片比视口高就贴底），
  Node 里 11 项用例。DOM 那半只用 rAF 每帧 place，位置没变就不写 style。
- 浮动条隐藏用 `opacity + pointer-events` 而不是 `display: none` ——
  隐藏态也要参与布局，否则构造时读不到 offsetWidth，第一次弹出会先落左上角再跳过来。
- 顺手补的 bug：`applyTree` 之后没人调 `paintSelection()`，所以**结构重建后选中态会丢**
  （折叠再展开、拖一次节点之后按 Tab 会莫名多出一个子级）。现在在 applyTree 出口统一挂回去。

### 折叠动画「奇怪 + 卡顿」
两个独立成因，都不是性能问题本身：
1. **连线比节点晚一帧**。d3 在 rAF 回调里写 transform，旧代码把重绘排进**下一个**
   rAF 合并 —— 线永远画在上一帧的位置，看起来在追节点。
   改成 MutationObserver 回调里**同步**画（MO 回调在微任务里，紧跟 d3 的 rAF，
   仍在同一帧渲染之前）。rAF 合并只留给全量绘制（那个必须等 markmap relayout）。
2. **卡片不跟着淡出**。markmap 折叠时把子树 `transform` 过渡到父节点位置，
   但只把 **foreignObject**（文字）的 opacity 过渡到 0。我们自绘的 rect/path/circle
   不知道这回事 → 文字正常淡出，一堆彩色方块和曲线继续往父节点飞，然后啪一下被删。
   展开时反过来：方块凭空出现再飞出去。现在 `syncFade` 把 fo 的内联 opacity
   同步到三个自绘元素上；**正在消失的节点冻结连线形状**（否则按被拖动的 transform
   反推出来的路径会被拉成又长又歪的曲线），跟着卡片一起淡掉。

### 性能
- 去掉每帧 `svg.querySelectorAll("g.markmap-node")`：painter 维护 `path → g` 索引，
  paintMoved 直接吃 MutationObserver 给的 g 元素，父节点查表。实测 paintMoved
  期间 querySelectorAll 调用 0 次。
- 淡出中的节点走快速路径：只读写 opacity，不 readNodeBox。
- `readNodeBox` 里 `querySelector(":scope > foreignObject")` 换成遍历 firstElementChild，
  省掉选择器解析（每帧几百次）。
- MutationObserver 的 childList 判定收窄：只有「节点 g 本身被增删」才算结构变化。
  我们自己往 g 里插卡片/连线也会产生 childList，不排除的话每次首绘都会多跑一次全量。
- 验证：painter 行为 14 项（mock SVG）、浮动条定位 11 项、工具栏 240~420px 实测
  行高恒为 37 / 不溢出 / 不换行。
- 1.11.0（299.3KB）已构建部署（sha1 校验）。

## 1.12.0 浮动条能关掉了 + 导出 SVG

### 关不掉的原因
`onNodeClick` 里点空白是 `if (!g) return` —— 直接吞掉，什么都清不了。
浮动条只能换目标，永远挂在某一卡片下面。三个出口补齐：
1. **点画布空白** → `setSelectedLine(-1)`，这是最自然的手势；
2. **浮动条末位「×」**（icon `x`，动作 `deselect`），浮出来的东西得有明确的关闭按钮；
3. **Esc 兜底**：`document` 级 keydown（`onGlobalKeyDown`），因为画布的 keydown 只在
   焦点在画布上时才收得到，点过工具栏/侧栏之后焦点就跑了。判据要排除
   `phase === "editing"`（编辑框的 Esc 是撤销本次编辑）和 `canvas.contains(target)`
   （画布内已有专门处理，否则一次 Esc 会关两次东西）。

顺带修 `NodeBar.attach(null)` 的空转：原来 `target !== this.target` 才走分支，
`null → null` 会落到 `this.start()`，每帧起一个 `place()` 然后立刻 `return`。
现在「同一个目标」统一直接处理，已收起时什么都不做。

### 导出 SVG（`src/export/svg.ts`）
不能 `outerHTML` 一存了事的三个原因，每个都会让导出图明显错：
1. **缩放**：d3-zoom 把 transform 写在最外层 `<g>` 上，存的只是「当前视口」。
   导出要清掉它、用 `mm.state.rect` 当 viewBox —— 得到整张图。
   注意 rect 是**内容包围盒**（fit 里也是拿它算 translate/scale 的），不是屏幕坐标。
2. **样式**：节点文字是 `foreignObject` 里的 HTML，样式来自主题 + 插件 styles.css。
   文件离开 Obsidian 就全失效。要按 `getComputedStyle` 把字体/颜色/底色/边框/
   内边距**内联**到克隆体上（原件与克隆体按下标一一对应，必须读原件）。
   刻意不全抄：一张 100 节点的图会到百万字符。挑 17 个决定观感的属性 + padding + border。
3. **背景**：SVG 默认透明，深色主题的浅色文字进白底阅读器就没了。
   画布自己通常 transparent（底色来自 `.view-content`），要逐级往上找。

- 纯函数 `exportViewBox` / `isOpaqueColor` / `exportFileName` 抽出单测 32 项。
  `isOpaqueColor` 必须读 alpha 分量：**`rgb(0,0,0)` 是纯黑，用 `/0\)$/` 之类会误判成透明**。
- 导出还顺手清掉 `obmind-selected`、`opacity` 残留（折叠动画跑到一半时导出会有一半看不见）。
- 用 `<img src="data:image/svg+xml,...">` 做验收：img 里的 SVG 是**完全隔离的文档**，
  不继承页面 CSS —— 它渲染正常才真正证明「离开 Obsidian 也能看」。
  实测 636×236 / 4 个节点 / 外层 g 的 transform 已清 / 节点自身 translate 保留 /
  标题、内联样式、背景 rect 都在。
- 写到笔记同目录 `<笔记名>.mindmap.svg`，同名**覆盖**（反复导出不该堆一串 -2/-3）。
- 工具栏新增 download 图标按钮，与 fit/refresh 同组。
- 1.12.0（309.3KB）已构建部署（sha1 校验）；浮动条开关 17 项浏览器用例全过。

## 1.15.0：编辑体验对齐全 XMind（四条反馈）
用户：「编辑操作体验一般，我想要 xmind 一样的编辑体验」，附四条：
① Ctrl+A 全选删到头不删节点；② 编辑完 Tab/Enter 常丢选中框；③ 有时只渲染一半图；④ 仍有轻度闪烁。

用真实 markmap 的探针（`tmp/probe.ts`，照抄 View 时序：setData(duration:0) →
dropDetached → reset → paintAll，并挂同款观察器）把 ②③ 复现成了确定性事实：

1. **选中框消失的根因**：markmap `renderData` 里有一句 `w.attr("class", …)`，
   把每个节点的 class 整个重写。实测打完标记再逼一次重排，class 从
   `markmap-node obmind-selected` 变成 `markmap-node` —— 选中 class 被抹掉，
   而内存里的 `selectedLines` 还在。**每次内容尺寸变化都会触发它**（它自己的
   ResizeObserver 100ms 防抖 → renderData），所以「编辑完就丢」。
   修法：观察器加 `attributeName === "class"`，`paintSelectionOn(els)` 只补
   「本该选中、现在没有」的节点。实测补一次就回、写同值不产生新记录（无死循环）。
2. **「只渲染一半图」的根因**：`paintAll` 把 `fo.style.opacity` 当静态快照抄给卡片，
   而 enter 节点这一瞬就是 0。以前靠「后面还有 transform 写入 → 再画一次」兜底；
   一旦这次绘制被 `blocked()`（快速连按 Enter 时第二轮回重建）挡掉，卡片就永久停在
   opacity 0。实测：42 个节点里 29 个卡死 → 半张图连卡片带底都没了。
   修法：观察器加 `style`（只认 foreignObject 的），`NodePainter.syncFadeFor`
   做**事件驱动**的透明度跟随，且**不过 blocked 闸门**（这一步不读布局）。
   关掉这条通道后 29 个卡死；打开 20 帧内全部恢复 —— 对比实验已记在探针里。
3. **空文本删除**：`EditService.commit` 以前「空文本一律放弃修改」→ 字删完按回车
   节点还在、旧文字回来了。改成**清空即删节点**（整棵子树，撤销可回）；编辑框里
   `Delete` 和 `Backspace` 都认空文本删除（以前只认 Backspace，全选后用 Delete 的人
   按到天亮也不删）；清空后给 placeholder「退格 / Delete 删除该节点」。
4. **提交即预览**（`MindmapView.previewText`）：编辑框一关，字会先退回旧内容等写盘
   （十几到几十毫秒）再跳到新内容 —— 这就是那下「闪」。现在用**同一个 renderInline**
   先把新文字铺到卡片上（连 fo 宽高一起改，再 `frames.paintNow()`），写盘在后面跑；
   真实投影到达时内容逐字节相同，`applyPatch` 里加了「innerHTML 相同就不赋值」，
   视觉上零切换。写失败/计划作废用返回的 revert 句柄把 DOM 退回旧内容。
5. **兜底**：`paintAll` 返回「读不到几何的节点数」，`FrameScheduler.paintNow` 隔帧重试
   ≤3 次（这些节点原本永远没有卡片）；`paintMoved` 首次见到的节点补齐
   样式/尺寸/收放点（以前只建空 rect）。
6. 编辑框：`place()` 加输入签名缓存（位置+fo 尺寸+文本），follow 循环 240ms 无变化
   就收尾 —— 以前打开后 420ms 内每帧写样式+读 scrollHeight，等于每帧强制同步布局。

placeholder 出现、class 被抹后补回 1 次、fade 事件救回 29 个僵死卡片。

## 1.16.2：查清「闪烁」的成因并修掉（markmap 的 100ms 防抖 + 180ms 过渡）
用户问「闪烁是什么原因啊」。没有猜，写了逐帧探针 `tmp/probeFlicker.ts`：
真实 markmap + 我们的 painter，照 applyTree/applyPatch 的时序，每帧记
「节点数 / 卡片数 / 无尺寸卡片 / 透明节点 / 幽灵节点 / 卡片两两重叠」。

结论（可复现的数字）：
- **结构重建**很干净：加一个节点，`setData(duration:0)` + dropDetached + paintNow
  在一帧内完成，只有第 1 帧有 1 个 enter 节点 opacity 0（被 syncFade 抄成透明卡片，
  下一帧就回）。所以「闪」不是重建造成的。
- **改一个字才是主因**：`renderData` 里 markmap 对每个节点的内容 div 挂了
  `ResizeObserver(debounce(..., 100))`，要等 100ms 才重排；重排的位置变化又走
  `options.duration`（180ms）的 transition。所以「卡片已经变宽、孩子那一列还停在
  旧位置」的错位会持续 **233ms**（实测：改一个分支标题后卡片互相压住，从 8ms
  一直持续到 233ms）。肉眼就是「压住一下、再滑开」。
- 对照实验：同样改长文字，改成「主动 duration 0 renderData」后重叠帧 **0**。

修法（`MindmapView.reflowSoon/reflowNow`）：尺寸变了别等 markmap 的防抖 ——
下一帧把 duration 置 0 主动 `renderData()`（位置瞬间到位），再 `paintNow()` +
`paintSelection()`（renderData 会整段重写 class，选中标记会被抹掉）。
`applyPatch` 里加 `changed` 判断（previewText 已经铺过内容就不重复排）；
`previewText` 与它的 revert 都改调 `reflowSoon()`（原来只是 paintNow，
只重画卡片不挪列，等于压住邻居）。

tsc 过、ALL PASS、冒烟 OK。构建 351.0KB，部署 sha1 `8b59bdb8…`。

## 1.16.3：查清「新建节点闪」（上一轮把方向找错了）
用户确认：「是新建节点这一类会闪烁」。1.16.2 我测的是「改一个字」的 patch 路径，
断言「结构重建很干净」—— 那次只有全量 audit，没有逐帧采样，所以没看见。

新探针 `tmp/probeNew.ts` 复刻 createNode 的完整时序（写盘 30ms → applyTree →
flushPendingEdit 两帧 → openInlineEditor），每帧记节点/卡片/零宽/透明/字隐/编辑框位置
以及所有卡片几何签名。43 节点树、插入一行，结果：

- 关掉护栏（`?noguard`）：**36ms 有 36 个节点文字 opacity 0，54ms 有 36 个卡片透明**
  —— 43 个节点里 36 个卡片整帧消失。这就是「闪」。
- 加护栏后：除了编辑框自己隐藏的那 1 个，全程 0。

机制：markmap 的节点 key 里带**孩子序号**，插入/删除一行 → 后面所有兄弟 key 变 →
d3 当新节点重新 enter → 写 `opacity: 0` 再起过渡；而 `duration: 0` 的过渡**仍然异步到
下一帧**，`setData` 内部的 await 正好让浏览器画了这一帧。更糟的是我们同步全量绘制
把这个 0 抄给了卡片。

实现：
1. `MindmapView.inFadeGuard()`：`rebuilding` 期 + 结束后 50ms 内，foreignObject 上
   < 1 的 opacity 当场抹成 `""`（observer 回调是微任务，赶在绘制前）。
   `phase === "editing"` 豁免（那里的 opacity 0 是编辑框防重影用的）。
2. `clearFade()`：setData 返回后清掉所有残余 opacity（`removeProperty`）。
3. `measureMissing()`：只给缺 width/height 的 fo 补一次 `scrollWidth/scrollHeight`,
   否则新节点第一帧没有卡片。
4. `reflowNow()` 开头与 await 后都查 `rt.phase !== "idle"` 直接返回 —— 它可能撞进
   重建期，把半成品 DOM 重排一遍。

验证：tsc 过、`npm test` ALL PASS、探针在 18 与 43 节点两种规模下透明/字隐均为 0
（编辑框那 1 个除外）、冒烟 OK。构建 355.0KB，部署 sha1 `a44e10be…`。
