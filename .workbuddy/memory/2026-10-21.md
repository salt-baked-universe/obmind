## 主题系统重做：XMind 风格视觉主题
- 反馈：之前的"主题"只换线条/文字色，不是 XMind 那种成体系的视觉主题。
- theme.ts 重写：`ThemeSpec` 描述一整套视觉（bg / 分支色板 / rootBg+rootFg / level1Solid / level1Fg / nodeText / tint / mixBase / circle / card / radius / linkWidth）。
- 5 套主题：classic（经典：白底+一级实色分支+深层同色浅底）、business（商务：蓝灰底+白卡片+深蓝根）、dark（深色）、candy（糖果：马卡龙大圆角）、minimal（极简：无卡片、分支色文字、细线）；`follow` 自动映射 classic/dark。
- 配色分配：`branchIndex(path)` 取 `state.path` 第二段 → 一级分支各自一色；`nodeStyleAt(spec, depth, branch)` 决定 bg/fg/bold；深层用 `mixColor(branch, mixBase, tint)` 生成同色系浅底。
- XMind 观感的关键：**节点卡片化**。markmap 的 DOM 为 `foreignObject.markmap-foreign > div > div`，给该内层 div 加 padding/border-radius/background/box-shadow；遍历 `g.markmap-node` 用 d3 挂在元素上的 `__data__` 拿 `state.depth/path`，把 `--obmind-node-bg/--obmind-node-fg` 写到 g 上由 CSS 继承。
- 折叠/展开时 markmap 自行增删节点（不走 setData），用 MutationObserver(childList+subtree) + 30ms 节流兜底重刷样式。
- 其他：`Markmap.create` options 传自定义 `color(node)` 函数（根用 rootBg，其余按分支色），paddingX 6 / spacingHorizontal 68 / maxWidth 380（卡片）；CSS `.markmap-link{stroke-width:var(--obmind-link-width)}` 覆盖 presentation attribute；节点内 `<a>` 改 `color:inherit`（实色卡片上蓝链接看不清）。
- 构建 160KB 已部署。

## 修复：卡片塌成细线 + 双链被括号截断
- 现象1：节点卡片渲染成「一条细线托着文字」，完全不像卡片。
- 关键坑（实测结论，务必记住）：**不能改 markmap 内部 DOM 的样式**。`foreignObject > div > div` 那层写背景/内边距，会被 markmap 每次重排重建并冲掉；用 box-shadow spread 也一样。表现就是卡片只剩节点自带的那条横线。
  验证方法：用 Edge headless（`msedge --headless=new --screenshot`）打开本地 demo 截图 + `--dump-dom` 看真实 DOM；连续 paint 会被 markmap 覆盖，只有它在 DOM 里插入 `<rect>` 才稳定。
- 最终方案：**在每个 `g.markmap-node` 里插入一个 `<rect class="obmind-node-card">` 作为第一个子元素**。
  - 用节点局部坐标绘制（x = 6 - padX，y = -padY，w = fo.width + 2padX，h = fo.height + 2padY），自动跟随 g 的 transform，无需任何坐标换算。
  - 尺寸直接取 `foreignObject` 的 width/height 属性（markmap 已算好，实测准确）。
  - 圆角 rx、fill 按分支色；`fo.style.color` 设文字色（这个能保留）。
  - 层级用 `state.path` 段数算（`path.split(".").length - 1`），比 `state.depth` 可靠。
- 现象2：`[文字](a%20(b).md)` 被 `(b)` 的右括号截断，剩下 `%20...` 裸文本。修复：链接 URL 正则允许一层括号 `\(((?:[^()\s]|\([^()]*\))+)\)`，站内链接 decodeURIComponent 后去掉 `.md`。
- markmap 尺寸铁律：**字体/字号/行高必须在其测量前定好**（`--markmap-font` 在 create 前设置），一旦测量后改字号/字重/padding 就会与 foreignObject 尺寸脱节，内容被裁剪。所以 paint 只改 fill/color/圆角这类不影响布局的属性。
- MutationObserver 防重入：插 rect 会触发自己的 observer，用 `painting` 标志 + 30ms 节流。
- 构建 162KB 已部署。

## 修复：连线改成 XMind 风格（接卡片垂直中心）+ 折叠圆点居中
- 反馈：markmap 的入线接在卡片**底边**并横穿卡片下方，XMind 是接卡片**垂直中心**、从边缘平滑进入。
- 实测结论：markmap 两处都改不动——
  1. 连线 `path.markmap-link` 的终点固定为节点矩形底边（源码里 `[v.x+v.width, v.y+v.height]`），没有选项可调；
  2. 每个节点还有一条装饰下划线 `<line x1=... y1=h+dy>`（就是最初"线托着文字"的那条），位置在内容底部，会横在卡片内部。
  处理：CSS 里 `path.markmap-link{display:none}` + `g.markmap-node > line{display:none}`，连线全部自绘。
- 自绘连线（`paintLink`）：在**子节点自己的 g 内**插 `path.obmind-node-link`，用局部坐标——
  起点 = 父卡片右边缘中点 `parent.ox + 6 + parent.w + parent.padX - ox`，`parent.oy + parent.h/2 - oy`；
  终点 = 子卡片左边缘中点 `6 - padX`，`h/2`；三次贝塞尔，控制点 `max(10, |span|*0.45)`。局部坐标自动跟随 translate 与缩放，无需屏幕坐标换算。
  插入位置 `g.insertBefore(link, card)`（在卡片之前 → 卡片后绘制，盖住线头）。
- 折叠圆点：markmap 把 `circle` 放在节点右下角 (w, h)，卡片比内容框大一圈就显得不居中。paintCard 里把 `cx = 6 + w + padX`、`cy = h/2`，挪到卡片右边缘垂直中心（与 XMind 一致）。
- **关键坑**：折叠/展开时 markmap 只改其它节点 g 的 `transform` 属性（重新布局），不增删 DOM，所以只观察 childList 的 MutationObserver 不会触发 → 自绘连线的 `d` 停在旧坐标，表现为线缩成卡片边上一小段。修复：observer 增加 `attributes: true, attributeFilter: ["transform"]`。
- 验证：`.preview` 里用 Edge headless 模拟点击 circle 折叠/展开后分别截图，确认圆点居中、展开后连线全部正确。
- 另：markmap `renderData` 里 `c.children.map(...)` 要求**每个节点都有 children 数组**（叶子也要 `children: []`），否则报 `Cannot read properties of undefined (reading 'map')`。parser.ts 的 buildTree 已保证，预览脚本曾漏掉。
- 构建 165.9KB 已部署。

## 性能重构：渲染分层 + 消除动画卡顿与缩放抖动
- 反馈：动画不流畅、缩放抖动；要求架构合理、高性能。
- 三个性能根因（实测定位）：
  1. **每个节点卡片挂 `filter: drop-shadow`** → 每节点一张离屏缓冲，缩放/动画必掉帧。改为「偏移 2px 的半透明 `<rect>` 当阴影」，纯填充零滤镜。
  2. **MutationObserver 监听整个 svg 的 transform** → 滚轮缩放改的是外层 g，却每帧触发全量重绘。改为只认 `target instanceof SVGGElement && classList.contains("markmap-node")`（节点局部布局变化），缩放/平移不再触发。
  3. **每帧全量 setAttribute + 读写交错** → 强制同步布局。改为读写分离（先收集所有 NodeBox，再统一写）+ 三组签名缓存（`style` / `geom` / `linkSig`），没变就不写。
- 新增架构（视图与渲染解耦）：
  - `src/render/geometry.ts`：纯函数。`readTranslate`（只 getAttribute，**禁用 baseVal.consolidate/getBBox/getComputedStyle**，会强制布局）、`readNodeBox`、`cardRect`、`cardRightX/CenterY`、`linkPath`、`depthOf/parentPathOf`。
  - `src/render/painter.ts`：`NodePainter`。read 阶段收集 boxes → write 阶段按签名写。`ensureLayers` 保证 z 序 shadow→link→card→markmap 原有内容，已有序时零 DOM 操作。
  - `src/MindmapView.ts`：只管视图生命周期 / 工具栏 / 事件 / 选笔记，绘制全部委托 painter。
- 重绘调度：`requestAnimationFrame` 合并同帧多次请求（替代 setTimeout 30ms）。
- 刷新优化：缓存 `lastContent` + `appliedThemeKey`，内容与主题都没变（如光标移动触发的 editor-change）直接跳过 `setData`，避免反复重排 + autoFit 造成的画面跳动。`setOptions` 仍只在主题变化时调用。
- 验证（.preview 用 esbuild 打包**真实** render 层 + theme，非复刻）：缩放模拟 delta=0（改前每帧都画）、avgPaintMs≈0.5（12 节点）、折叠/展开截图连线与圆点均正确。
- 构建 169.6KB 已部署。

## 折叠抖动 + 缩放被重置（根因都在 markmap 的 autoFit）

用户反馈"抖动就在收放点上、收起后回到默认缩放级别"。查 markmap-view/dist/index.js 定位到：
- L706 `n && this.fit()`（n=options.autoFit）：**每次 render 结尾都 fit**，而 toggleNode→renderData→render 是同一路径。
- L786 `this.transition(this.svg).call(this.zoom.transform, c)`：fit 本身是 180ms 缩放+平移动画。
- L692 `D.attr("cx", r => r.state.rect.width)`：circle 位置每次 render 重置回内容右下角。
- L694 `this.transition(w).attr("transform", ...)`：节点 g 的 transform 也是 180ms transition，每帧都变。
→ 点圆点 = 全图重排 + 全图重新 fit（缩放动画）；同时圆点是我在 painter 里每帧抢写 cx/cy，与 markmap 打架 → 抖在收放点。

修复：
1. `autoFit: false` + `fitInstant()`（setOptions duration=0 → fit → 恢复）；只在首开/换笔记时调，打字不调。工具栏加「适配」按钮。注意 `Markmap.create(svg, opts, data)` 内部会 fit，改为不传 data、先 create 再 setData。
2. circle 改用 `style.transform: translate()` 平移，不再写 cx/cy（d3 写属性、我们写内联样式，叠加不冲突）。CSS 加 `transform-box: view-box` + 0.12s transition。
3. painter 拆 `paintAll` / `paintLinks(only)`；`sizeSig` 只认 `w|h`（原来含 ox/oy，导致折叠动画每帧重写卡片尺寸）。observer 分流：childList→全量，节点 g transform→只刷连线（O(变化节点)）。
4. `refresh()` 内容与主题都没变时直接 return（不再重绘）。

验证（headless Edge + 真实 painter）：折叠前后 `svg.__zoom` 完全一致 `2.00000|77.00|349.38`（两次都是 zoom kept=true）；动画期间 16ms 采样 circle transform 只有 1 个值；数据层可见节点 11→6→11。**注意**：headless 的 virtual-time 下 d3 transition 不推进，DOM 里的 exit 节点不会消失，不能用"节点数量减少"判断折叠是否生效，要看 `state.data` 的 fold 或自写遍历。
- 构建 175.2KB 已部署。
