## 修复：卡片塌成细线 + 双链被括号截断
- 现象1：节点卡片渲染成「一条细线托着文字」，完全不像卡片。
- 关键坑（实测结论，务必记住）：**不能改 markmap 内部 DOM 的样式**。`foreignObject > div > div` 那层写背景/内边距，会被 markmap 每次重排重建并冲掉；用 box-shadow spread 也一样。表现就是卡片只剩节点自带的那条横线。
  验证方法：用 Edge headless（`msedge --headless=new --screenshot`）打开本地 demo 截图 + `--dump-dom` 看真实 DOM；连续 paint 会被 markmap 覆盖，只有它在 DOM 里插入 `<rect>` 才稳定。
- 最终方案：**在每个 `g.markmap-node` 里插入一个 `<rect class="obmind-node-card">` 作为第一个子元素**。
  - 用节点局部坐标绘制（x = 6 - padX，y = -padY，w = fo.width + 2padX，h = fo.height + 2padY），自动跟随 g 的 transform，无需任何坐标换算。
  - 尺寸直接取 `foreignObject` 的 width/height 属性（markmap 已算好，实测准确）。
  - 圆角 rx、fill 按分支色；`fo.style.color` 设文字色（这个能保留）。
  - 层级用 `state.path` 段数算（`path.split(".").length - 1`），比 `state.depth` 可靠。
- 现象2：`[文字](a%20(b).md)` 被 `(b)` 的右括号截断，剩下 `%20...` 裸文本。修复：链接 URL 正则允许一层括号 `\(((?:[^()\s]|\([^()]*\))+)\)`，站内链接 decodeURIComponent 后去掉 `.md`。
- markmap 尺寸铁律：**字体/字号/行高必须在其测量前定好**（`--markmap-font` 在 create 前设置），一旦测量后改字号/字重/padding 就会与 foreignObject 尺寸脱节，内容被裁剪。所以 paint 只改 fill/color/圆角这类不影响布局的属性。
- MutationObserver 防重入：插 rect 会触发自己的 observer，用 `painting` 标志 + 30ms 节流。
- 构建 162KB 已部署。

## 修复：连线改成 XMind 风格（接卡片垂直中心）+ 折叠圆点居中
- 反馈：markmap 的入线接在卡片**底边**并横穿卡片下方，XMind 是接卡片**垂直中心**、从边缘平滑进入。
- 实测结论：markmap 两处都改不动——
  1. 连线 `path.markmap-link` 的终点固定为节点矩形底边（源码里 `[v.x+v.width, v.y+v.height]`），没有选项可调；
  2. 每个节点还有一条装饰下划线 `<line x1=... y1=h+dy>`（就是最初"线托着文字"的那条），位置在内容底部，会横在卡片内部。
  处理：CSS 里 `path.markmap-link{display:none}` + `g.markmap-node > line{display:none}`，连线全部自绘。
- 自绘连线（`paintLink`）：在**子节点自己的 g 内**插 `path.obmind-node-link`，用局部坐标——
  起点 = 父卡片右边缘中点 `parent.ox + 6 + parent.w + parent.padX - ox`，`parent.oy + parent.h/2 - oy`；
  终点 = 子卡片左边缘中点 `6 - padX`，`h/2`；三次贝塞尔，控制点 `max(10, |span|*0.45)`。局部坐标自动跟随 translate 与缩放，无需屏幕坐标换算。
  插入位置 `g.insertBefore(link, card)`（在卡片之前 → 卡片后绘制，盖住线头）。
- 折叠圆点：markmap 把 `circle` 放在节点右下角 (w, h)，卡片比内容框大一圈就显得不居中。paintCard 里把 `cx = 6 + w + padX`、`cy = h/2`，挪到卡片右边缘垂直中心（与 XMind 一致）。
- **关键坑**：折叠/展开时 markmap 只改其它节点 g 的 `transform` 属性（重新布局），不增删 DOM，所以只观察 childList 的 MutationObserver 不会触发 → 自绘连线的 `d` 停在旧坐标，表现为线缩成卡片边上一小段。修复：observer 增加 `attributes: true, attributeFilter: ["transform"]`。
- 验证：`.preview` 里用 Edge headless 模拟点击 circle 折叠/展开后分别截图，确认圆点居中、展开后连线全部正确。
- 另：markmap `renderData` 里 `c.children.map(...)` 要求**每个节点都有 children 数组**（叶子也要 `children: []`），否则报 `Cannot read properties of undefined (reading 'map')`。parser.ts 的 buildTree 已保证，预览脚本曾漏掉。
- 构建 165.9KB 已部署。

## 性能重构：渲染分层 + 消除动画卡顿与缩放抖动
- 反馈：动画不流畅、缩放抖动；要求架构合理、高性能。
- 三个性能根因（实测定位）：
  1. **每个节点卡片挂 `filter: drop-shadow`** → 每节点一张离屏缓冲，缩放/动画必掉帧。改为「偏移 2px 的半透明 `<rect>` 当阴影」，纯填充零滤镜。
  2. **MutationObserver 监听整个 svg 的 transform** → 滚轮缩放改的是外层 g，却每帧触发全量重绘。改为只认 `target instanceof SVGGElement && classList.contains("markmap-node")`（节点局部布局变化），缩放/平移不再触发。
  3. **每帧全量 setAttribute + 读写交错** → 强制同步布局。改为读写分离（先收集所有 NodeBox，再统一写）+ 三组签名缓存（`style` / `geom` / `linkSig`），没变就不写。
- 新增架构（视图与渲染解耦）：
  - `src/render/geometry.ts`：纯函数。`readTranslate`（只 getAttribute，**禁用 baseVal.consolidate/getBBox/getComputedStyle**，会强制布局）、`readNodeBox`、`cardRect`、`cardRightX/CenterY`、`linkPath`、`depthOf/parentPathOf`。
  - `src/render/painter.ts`：`NodePainter`。read 阶段收集 boxes → write 阶段按签名写。`ensureLayers` 保证 z 序 shadow→link→card→markmap 原有内容，已有序时零 DOM 操作。
  - `src/MindmapView.ts`：只管视图生命周期 / 工具栏 / 事件 / 选笔记，绘制全部委托 painter。
- 重绘调度：`requestAnimationFrame` 合并同帧多次请求（替代 setTimeout 30ms）。
- 刷新优化：缓存 `lastContent` + `appliedThemeKey`，内容与主题都没变（如光标移动触发的 editor-change）直接跳过 `setData`，避免反复重排 + autoFit 造成的画面跳动。`setOptions` 仍只在主题变化时调用。
- 验证（.preview 用 esbuild 打包**真实** render 层 + theme，非复刻）：缩放模拟 delta=0（改前每帧都画）、avgPaintMs≈0.5（12 节点）、折叠/展开截图连线与圆点均正确。
- 构建 169.6KB 已部署。

## 折叠抖动 + 缩放被重置（根因都在 markmap 的 autoFit）

用户反馈"抖动就在收放点上、收起后回到默认缩放级别"。查 markmap-view/dist/index.js 定位到：
- L706 `n && this.fit()`（n=options.autoFit）：**每次 render 结尾都 fit**，而 toggleNode→renderData→render 是同一路径。
- L786 `this.transition(this.svg).call(this.zoom.transform, c)`：fit 本身是 180ms 缩放+平移动画。
- L692 `D.attr("cx", r => r.state.rect.width)`：circle 位置每次 render 重置回内容右下角。
- L694 `this.transition(w).attr("transform", ...)`：节点 g 的 transform 也是 180ms transition，每帧都变。
→ 点圆点 = 全图重排 + 全图重新 fit（缩放动画）；同时圆点是我在 painter 里每帧抢写 cx/cy，与 markmap 打架 → 抖在收放点。

修复：
1. `autoFit: false` + `fitInstant()`（setOptions duration=0 → fit → 恢复）；只在首开/换笔记时调，打字不调。工具栏加「适配」按钮。注意 `Markmap.create(svg, opts, data)` 内部会 fit，改为不传 data、先 create 再 setData。
2. circle 改用 `style.transform: translate()` 平移，不再写 cx/cy（d3 写属性、我们写内联样式，叠加不冲突）。CSS 加 `transform-box: view-box` + 0.12s transition。
3. painter 拆 `paintAll` / `paintLinks(only)`；`sizeSig` 只认 `w|h`（原来含 ox/oy，导致折叠动画每帧重写卡片尺寸）。observer 分流：childList→全量，节点 g transform→只刷连线（O(变化节点)）。
4. `refresh()` 内容与主题都没变时直接 return（不再重绘）。

验证（headless Edge + 真实 painter）：折叠前后 `svg.__zoom` 完全一致 `2.00000|77.00|349.38`（两次都是 zoom kept=true）；动画期间 16ms 采样 circle transform 只有 1 个值；数据层可见节点 11→6→11。**注意**：headless 的 virtual-time 下 d3 transition 不推进，DOM 里的 exit 节点不会消失，不能用"节点数量减少"判断折叠是否生效，要看 `state.data` 的 fold 或自写遍历。
- 构建 175.2KB 已部署。


## 双向编辑（导图改字 → 回写笔记）

用户问"能不能加双向编辑"，确认范围：文字 + 结构操作（Enter/Tab/Shift+Tab/退格删行），
单击跳转改为 Ctrl/⌘+单击，双击专职编辑。

### 三道坎与解法
1. **节点↔源行映射丢失**。`buildTree` 原先只产 IPureNode，没留行号。现在每个非根节点挂
   `payload.src: SrcRef`（line/bodyStart/bodyEnd/full/marker/indent/checked/text/heading），
   根节点挂 `payload.step`。`payload` 会透传到 `g.__data__`，且不能用 `fold` 字段名（markmap 保留）。
2. **回写必须行内片段替换**。`full.slice(0,bodyStart) + 新正文 + full.slice(bodyEnd)`，
   缩进/列表符号/引用前缀/行尾空白全部原样保留。写前用 `full` 做锚点校验，对不上就中止并 Notice。
   有打开的编辑器走 `editor.transaction`（保留光标与 Ctrl+Z），否则 `vault.process`。
3. **回环**：写文件 → editor-change → 300ms 重建 → 编辑框与光标一起没。加 `editing` 闸门，
   编辑期间 refresh 只记 `pendingRefresh`；提交后 `pendingRefresh=false` 再主动 refresh。

### 编辑框不能放 foreignObject
markmap 用 `firstChild.firstChild.scrollWidth/scrollHeight` 量节点尺寸，塞输入框进去布局必歪；
且每次 render 重建那层 DOM。改为挂在画布 div 上的 absolute 浮层，位置取 `fo.getBoundingClientRect()`，
`transform: scale(k)` 抵消画布缩放（k = 屏幕宽 / fo 的 width 属性）。

### 踩到的坑
- **dblclick 收不到**：markmap 在 foreignObject 上绑 `T(e){e.stopPropagation();}`，冒泡被掐断。
  必须 `svg.addEventListener("dblclick", h, true)` 走捕获阶段。
- **字体回退导致多折一行**：编辑框写 `var(--font-interface)` 在无宿主变量时回退成别的字体，
  文字变宽 → textarea 多一行 → 高度 49 vs 卡片 25。改为 `getComputedStyle(fo)` 逐个取
  fontFamily/fontSize/fontWeight/fontStyle/lineHeight/letterSpacing。
- **宽度差零点几像素也折行**：markmap 的节点宽是 scrollWidth 取整值，textarea 卡死同宽会多折一行，
  宽度给 `rawW + 2` 容差后高度完全对齐（实测 fo 58x25 / ta 60x25，dx=dy=0）。

### 折叠状态保持

## 1.1.1：空白画布 + 双向编辑手感

### 「打开一片空白，点适配才有内容」——根因是 fit 时容器宽度为 0

（之前是 `autoFit: true`，markmap 每次 render 都 fit，等布局好了自然会好；
关掉 autoFit 改成只 fit 一次后，这一次正好撞在尺寸 0 上。）

1. **中文输入法回车被当成提交**。`onKeyDown` 里 `e.key === "Enter"` 直接 finish，

2. **改完一个想改下一个，点过去没反应**。双击另一个节点时 `editing` 还是 true

   等提交+重建完由 `flushPendingEdit()` 自动接上。
3. 顺带：`refresh()` 的短路分支也要调 `flushPendingEdit()`，否则「没改内容就提交」

## 1.2.0：拖动改变父子关系（XMind 式）

用户需求：像 XMind 那样拖节点改层级。先统计了库里的结构——359 篇笔记，187 篇含标题、
297 篇含缩进、212 篇含列表，**混合结构是常态**，所以两套层级体系都得支持。

### 语义
拖到目标卡片**中部** → 成为子节点；**上沿** → 排前面；**下沿** → 排后面。

### 两条硬规则（否则会毁结构）
1. **标题与正文是两套层级体系**（`#` 数量 vs 缩进空格），混拖会互相破坏。
   只允许「标题↔标题」「正文↔正文」，外加「正文 → 标题下当子节点」（此时缩进归 0）。
   其余组合直接拒绝并提示。
2. 位移量一律**以目标节点为参照物**做相对计算，不去推导全局标题栈。
   早先想过算 headingStack.length，但混合结构下极易算偏；改成「目标缩进 + step」后
   完全不需要知道上下文。

### 为什么必须整篇替换
拖动让一行跑到很远的位置，中间所有行号都变。分成「先删后插」两次写，中间那一瞬
笔记就是坏的。所以 `moveNode` 一次性算出整篇新内容，`replaceAll` 一次写入
（有编辑器走 `editor.transaction` 全量 change，保留 Ctrl+Z；否则 `vault.process`）。

### 踩到的坑
- **「缩进没变」不等于「位置没变」**。最初用 `newSpaces === srcSpaces` 判「位置没变化」，
  结果同层的 A 拖到 B 前面（缩进相同但位置确实变了）被误拒。改成整篇结果逐行比对。
- **d3-zoom 抢 mousedown**。markmap 用 d3-zoom 绑画布平移，在节点上按下会变成拖画布。
  在 svg 捕获阶段对命中节点的 mousedown / pointerdown `stopPropagation`。
- **pointerdown 不能 preventDefault**，那会掐掉后续 click/dblclick，双击编辑就废了。
  改拖拽开始时 `document.body.style.userSelect = "none"`，reset 时恢复。
- **拖进自己子树**：用 markmap 的 `state.path`（"0.2.1"）判断，后代路径一定以
  `源路径 + "."` 开头，比算几何范围可靠。命中前就从候选里剔掉。

### 新增
- `src/edit/move.ts`：`moveNode` / `blockRange` / `collectSrc`，纯函数，可单测
- `src/edit/drag.ts`：`DragController`，命中判定 + 指示器 + 事件拦截
- `src/edit/writer.ts`：新增 `replaceAll`
- `parser.ts` 的 `SrcRef` 增加 `depth` / `level`

  正文拖到标题下、以及三种非法组合（拖进自己子树、标题拖正文、正文与标题平级）。
- headless Edge 模拟真实 PointerEvent：中部→box 显示、上下沿→line 显示、

## 1.2.1：写完文件导图不更新 + 拖动缩进错乱

### 「文件更新了，view 要手动刷新」——读的是磁盘旧内容
`readContent` 只认「活跃视图」：
```ts
const mdView = app.workspace.getActiveViewOfType(MarkdownView); // 拖导图时返回 null
if (mdView?.file?.path === file.path) return mdView.editor.getValue();
return app.vault.cachedRead(file);   // ← 落到这里
```
但写回走的是 `writer.findEditor`（扫所有 markdown leaf），写的是**编辑器缓冲**。
Obsidian 自动保存有延迟（约 2s），此刻 `cachedRead` 读盘拿到的还是旧内容 →
`refresh` 里 `content === this.lastContent` 命中短路 → 什么都不重建。
点「刷新」时会清 `lastContent`，且那时已落盘，所以又好了 —— 与现象完全吻合。

修复两层：
1. `readContent` 改用 `findEditor`（与写回同一套查找），没有编辑器才 `vault.read`
   （不用 cachedRead，刚写完读缓存同样可能旧）。
2. `refresh(knownContent?)` 增加可选入参，拖动写完后直接 `refresh(next)`，
   不再依赖「读回来的东西是新的」，把竞态彻底掐死。

### 拖动缩进错乱（多空格 / 层级忽然变深）——三处度量不一致
1. **制表符**：解析里 tab 算 1 层，`move.ts` 的 `spacesOf` 按 tab=4 空格算。
   制表符缩进的笔记（库里 126 篇）拖一次深度就翻倍。→ 统一用 `colsOfIndent`（tab=4 列）。
2. **引用行**：`> \t\t内容` 的缩进量在 `>` 之前（恒为 0），解析器量的是 `>` 之后，
   于是引用节点怎么拖缩进都不变。→ `splitLine` 先剥引用前缀再量。
3. **步长检测被单行带偏**：原来取「最小正缩进」，库里 47 篇笔记最小缩进是 1 空格
   （手误），整篇 step=1 → 缩进 2 空格被算成第 2 层，导图整片错乱。
   → `detectIndent` 取「能整除最多行的最小候选值」（需解释 ≥85% 的缩进行），
     并顺带得出 `indentUnit`（原文实际的空白串，可能是一个 tab）。

### 层级不再用 floor(列数/步长)
改成**缩进栈**：比栈顶深就进一层，比栈顶浅就弹回去；遇到标题重置栈。
好处：同一缩进永远算出同一深度。旧版还有个「相对上一行最多深 1 层」的钳制，
会造成 0空格(2层)→4空格(3层)→4空格(4层) 这种同缩进不同深度，
`blockRange` 判子树范围时提前截断，拖动把子节点落在原地。
装配树时改为「挂到最近的已存在祖先」，跳级不再挤到根节点上。

### 缩进量不再自己算
`childIndentCols` 直接沿用目标**第一个子节点**的缩进；没有子节点才用「目标 + 步长」，
标题下用 0。这样新兄弟与老兄弟的缩进逐字符一致，不会出现「多空格」。
`shiftBlock` 按列数平移后用 `renderIndent` 还原，优先用原文的 `indentUnit`。

### 验证
- 单行往返 `rewriteNode`：627 个真实节点逐字节一致，0 失败。
- 拖动：7706 个用例（12 篇 ≤80 节点的真实笔记 × 全部节点对 × child/before/after），
  重新解析后层级与预期**全部一致**，且块外行逐字符未动。另一轮 8876 用例（40 篇）同样 0 异常。
- 专项：Tab 缩进笔记拖动后仍输出 tab；引用行 `> \t\tX` 拖到标题下正确变成 `> X`。

## 1.2.3：拖动后 view 更新时「线乱飞闪一下」

### 三个叠加的原因
1. **setData 默认带 180ms 位置过渡**。`applyTree` 前没有任何控制，`mm.options.duration = 180`。
2. **结构变化会整篇重编孩子索引路径**（"0.2.1"），d3 按索引把 g 元素复用到**别的节点**上。
   实测：拖动后同一个 g 元素确实被复用给不同节点。过渡期间 g 里的旧卡片/旧连线
   先留在新节点身上，位置又在动 → 线从错的父节点出发。
3. **过渡期间 MutationObserver 每帧按半路位置重算连线**（attributeFilter 里监听 g 的 transform）。
   180ms 里每帧都画一条"半路"的线，叠加起来就是乱。

### 顺带发现的幽灵卡片
setData 里旧节点是 `transition(...).remove()`，**duration 0 也要等一个 tick** 才移走。
这期间它们文字已 opacity 0，但我们的卡片 rect 是不透明的 → 同步重绘会给它们画卡片。
实测：结构变化后 DOM 里有 **10 个 g（正确只有 6 个）**。

清理必须用**对象身份**（`g.__data__` 是否属于 `mm.state.data` 这棵树），
不能用 path —— 旧节点的 path 很可能和新树里某个节点撞上（都叫 "0.0.1"），
按 path 判断会漏（实测漏掉 1 个，7 个残留）；按身份判断 10 → 6，干净。

### 改法
新增 `applyTree(tree)` 收口重建：
1. `rebuilding = true`：期间 `requestPaint` 直接 return（半成品不画）；
2. `mm.setOptions({ duration: 0 })`——结构变化不需要过渡，本来就是整树换血；
3. `await setData` → `dropDetached()`（按身份清残留）→ `painter.reset()` → `paintAllSync()`；
4. finally 里还原 duration、`rebuilding = false`。

新增 `paintAllSync()`：取消挂起的 rAF，同步 `paintAll`。必须在浏览器绘制这一帧之前
把卡片/连线摆正，否则会先播出一帧「新位置节点 + 旧父节点连线」。

折叠/展开的 180ms 动画不受影响（那是 markmap 自己 toggleNode → render，只临时改了本次 setData 的 duration）。

### 验证（headless Edge + 真实 markmap/painter）
- 初版 6 节点、错线 0
- 结构变化后、重绘前：**错线 4 条**（子项 A2、分支甲、子项 B1、分支乙）—— 即旧行为那 180ms 屏幕上的样子
- 同步重绘后（同一 tick）：错线 0；节点数立刻回到 6
- 清残留：10 → 6
- duration 还原 180；仅改文字的重建：错线 0
判定标准：每条自绘连线的 `d` 是否等于「按它当前父节点几何算出来的 linkPath」。

- `parseFence()` 识别 ``` / ~~~ / `$$`（含单行 `$$x$$`，但行中间夹文字的 `$$` 属于行内公式，不算块）
- 未闭合围栏吃到文末
- `dedentBlock()` 按围栏行缩进逐行剥离：不剥的话，缩进 4 格会被 CommonMark 当成缩进代码块，渲染结果和原文不一致
- 块节点**不挂 src**（故意只读）：跨多行，改一行就会把块拆坏，所以双击/拖动都不作用在它身上

渲染走 `MarkdownRenderer.render(app, raw, el, file.path, component)`，不引 katex：
公式有 MathJax、代码有高亮，且和笔记里观感一致，打包体积不涨（223.4KB）。

三个必须注意的点：
1. **必须在 setData 之前渲染完**。markmap 是按 content 里 DOM 的 scrollWidth/scrollHeight 量节点尺寸的，
   先灌占位再替换内容，foreignObject 和实际文字会脱节。
2. **Component 要先 `load()`**。MarkdownRenderer 把高亮/MathJax 渲染器作为子组件 addChild 上来，
   父组件没 load 的话子组件不启动，公式会一直是原始 `$$…$$`。
3. **要缓存**。每打一个字都重建整棵树，几十个代码块的笔记每次按键重跑一遍高亮，输入会滞。
   缓存 key 用 `kind|lang|raw`（代码块里没有双链，不需要 file.path），上限 300 条。

### ② 切文件不同步：active-leaf-change 在同一个 leaf 里换文件不触发
原来只监听 `active-leaf-change`。用户在**同一个标签页**里换文件时 leaf 没变，这个事件不触发，
于是导图停在上篇。补 `file-open` 监听（`file.path === lastFilePath` 时跳过，避免多余重建）。

### ③ 行内 HTML：白名单透传
`renderInline` 一上来就 escapeHtml，`<span style="color:red">` 会变成字面文本。
改成 `splitInlineHtml()` 先按白名单把标签摘成 `\u0002N\u0002` 占位符，走完转义 + markdown 行内语法后再插回去。
- 标签白名单：span/font/mark/b/strong/i/em/u/s/del/sup/sub/br/small/big/kbd/abbr/q/cite/center
- style 只留 color/background/font-size/font-weight/font-family/text-decoration/line-height 等表现型属性，
  挡掉 `url()` / `expression()` / `javascript:` / `@import`
- 属性只认 style/color/face/size/align/class，`on*`、`href`、`src` 一律丢弃
- 标签内的文字仍会走 markdown 规则（`<span>**粗**</span>` → `<span><strong>粗</strong></span>`）
- 行内代码里的标签仍被当文本（`` `<span>` `` → code 里的字面标签）

### 踩到的坑：测量单位
验证块宽度时先报「长代码节点 470，超 380 上限」。查下来是**用 getBoundingClientRect 量 SVG 内部元素**——
BCR 是屏幕像素，会被画布 fit 的 scale（当时 1.38）放大。改用 `fo.getAttribute("width")` /
`card.width.baseVal.value`（SVG 用户单位）后是 340，完全正常。之前几轮量卡片也踩过同一个坑，但没意识到。

### CSS
`pre` 必须写死 `max-width: 320px`：markmap 的 maxWidth 只是设在 svg 上的 `--markmap-max-width`，
约束的是那层 div 的可用宽度，而 inline-block 的实际宽度由 pre 的 **max-content**（不折行的整行宽）决定——
一行 110 字符的代码能把节点撑到 700+。配合 `white-space: pre-wrap` + `overflow-wrap: anywhere` 折行。
公式 `mjx-container` 字号收到 92%（按 em 计算，14px 下会比节点文字大一圈）。

## 架构重构第 1 步（1.4.0）：运行时状态机 + 投影通道
- **关键技术发现（决定了整个性能方案）**：markmap 的 `state.key = 父id.子id + hash(content)`，
  内容一变 key 全变，`setData` 会让整棵树重新 enter（foreignObject/内容 DOM/高亮/公式全部重来）。
  而它对每个节点的内容 div 挂了 `ResizeObserver`（100ms 防抖 → `renderData()`），
  且 `foreignObject` 的 html 只在 enter 时写入、merge 不覆盖 —— 所以**改 DOM 就是它支持的增量路径**。
- 新增 `src/app/runtime.ts`：`ViewRuntime`，一个显式 phase（idle/editing/dragging/rebuilding）
  + rev 版本号 + 任务串行合并。替掉 refreshing/pending/rebuilding/pendingRefresh 四个布尔。
  规则：只有 idle 才跑重建，其余阶段挂起、回 idle 自动补跑（替代手写 pendingRefresh）。
- 新增 `src/app/plan.ts`：`planProjection()` 纯函数 → none / patch / structure。
  判据是「结构变了没有」而不是「内容变了没有」：树形逐节点比 line+depth，恰好一处 content 差异才 patch。
  **盲区**：块节点 content 是占位文案（`代码块 · js · 3 行`），块内代码变了树完全一样 →
  必须再比原文（`sourceSame`）。这是写用例才发现的，靠树比对会漏刷新。
- 新增 `src/render/frame.ts`：`FrameScheduler`，rAF 合并 + all/links 两模式 + 重建期屏蔽，
  从 View 搬出 paintFrame/paintMode/paintPaths。
- MindmapView：`applyPatch()` 原地改 `fo.firstElementChild.firstElementChild.innerHTML`，
  **刻意不重算 state.key**（一改就等于宣布新节点）；MutationObserver 增加 width/height 监听
  （内容尺寸变 → 卡片要全量重绘，原来只听 transform 只刷连线）。
- 验证：13 项投影判定 + 5 项状态机用例全过；真实 Chromium（Python Playwright）实测 patch：
  key 稳定、节点未重建、markmap 自行重排（孙节点 x 246→443）。
  **注意 headless `--virtual-time-budget` 下 rAF 不推进，测不到重排**，必须用 Playwright。
- mock 加载 11 项通过，含「残留视图类型不再死锁」。
