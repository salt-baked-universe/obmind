## 1.18.16 Windows 触摸板操作逻辑 + 缩放键

用户：「帮我做个 win 的触摸板的操作逻辑，现在只有鼠标的」。

**根因**：滚轮一直交给 d3-zoom，它只有「滚多少缩放多少」一个意思；markmap 用 UA 猜
（`scrollForPan` 只在 Mac 上默认 true），而 Windows 同一台机器上鼠标和触摸板是混用的。
于是触摸板双指轻轻一划 = 整张图放大到看不见。

**关键发现**（改之前必须先搞清楚，否则白改）：
- d3-zoom 的 `wheeled` 里有 `noevent(event)` = `preventDefault + stopImmediatePropagation`。
  只要 filter 放行 wheel，画布上挂的任何 wheel 监听都收不到 —— 所以「再加一个监听」没用，
  必须先把 d3 的 wheel 关掉。
- markmap 的 `pan: true` 会另绑一个 `svg.on("wheel", handlePan)`。两套同时存在时
  谁生效取决于构造顺序（d3 先绑，所以它 stopImmediatePropagation 之后 handlePan 是死代码）。
- `zoom.translateBy(sel, x, y)` 的 x/y 是**内容坐标**（内部 `t.translate` 会乘 k），
  平移要传 `dx/k`；`zoom.scaleBy(sel, k, p)` 的 p 是 svg 用户坐标（`getScreenCTM().inverse()`），
  两者都能在 d3 监听之外调用（第 4 个参数显式传 event，不依赖全局 `event`）。

**改法**：
- `render/wheel.ts`（纯）：`WheelGesture.classify(e, viewport)` + `looksLikeNotch` + `toPixels`。
  `ctrlKey`（捏合/Ctrl+滚轮）→ 缩放；`Shift` → 横移；**整格**（mode 0 + 无 deltaX + 100/120 倍数）
  才算鼠标 → 缩放，其余（零碎值、带横向分量）一律平移；手势内只允许 zoom→pan 单向改判
  （鼠标永远不会产生半格，回溯判定不会误反）。倍率夹紧 [0.5, 2]。
- `MindmapView`：`applyZoomFilter` 对 wheel 返 false、`buildOptions` 加 `pan:false`；
  `onWheel` 攒到下一帧一次 `scaleBy` / `translateBy`（触摸板 100Hz → 每秒 60 次重绘）。
  pan 用 `dx/k` 换算，实测屏幕位移精确等于 delta。
- 键盘兜底 `mod+= / - / 0`：Windows 精密触摸板的捏合不一定合成 ctrl+wheel（Electron 尤其飘），
  没有这组键，只用触摸板的人就没有任何缩放手段。`keyOf` 增加按 `code` 归一物理键位
  （Shift+= 送来的是 `+`、小键盘是 `Add`）。
- `styles.css`：`.obmind-canvas` 加 `overscroll-behavior: contain`。
- 帮助面板补 4 行（鼠标滚轮 / 触摸板双指 / 捏合 / 缩放键）。

**验证**：tsc 干净 / `npm test` ALL PASS（新增 T30 共 20 条，T29 补 6 条缩放键）/
469.3kb / smoke OK。
`tmp/wheelProbe.ts`（真 d3-zoom + 真 WheelEvent）量得：鼠标一格 k×1.149、锚点误差 **0**、
触摸板两格内容移 14px、k=1.149 时平移 30px 精确、捏合 k×1.149、**从 svg 冒泡上来也能收到**（这是关键，
证明 d3 没吞事件）；filter：wheel=false / 左键=false / 右键=true。

**为什么没做成设置项**：判定是逐手势的，鼠标和触摸板在同一台机器上混用，设置项反而要人去切换。

## 1.18.17 修 1.18.16 的回归：鼠标滚轮变平移

用户：「怎么鼠标滚轮变上下滑动了？不是细粒度的缩放吗，我似乎没有下这样的命令吧」。

**根因**：`looksLikeNotch` 把「鼠标一格」写成了 `|deltaY| === 100 或 120`，还带 `a < 50 return false`。
那是 Chromium 在 Windows **默认「一次滚 3 行」**下的换算结果。而 Windows 的滚动行数是用户可调的，
Chromium 的公式是 `行数 × 40`：滚 1 行 = 40、2 行 = 80、4 行 = 160、5 行 = 200。
只要设置不是 3 行，`% 100 !== 0 && % 120 !== 0` → 判成触摸板 → 走 `translateBy` → 滚轮变上下平移。
`a < 50` 还把「1 行 = 40」直接判死。

**改法**（`render/wheel.ts`）：
- `looksLikeNotch` → `looksLikeWheel`，判三件事：整数（容差 0.05）、`|dy| ≥ 28`、`|dx| ≤ 0.5`。
  不再有任何魔数；行/页模式仍直接算鼠标。
- **倍率按格算**：手势内记住首个 `|dy|` 当 `notchPx`（夹 28~400），`factor = 2^(-dy/notchPx * 0.2)`。
  一格永远 1.149 倍，40px/格 和 200px/格 手感一致。旧版按像素线性（`-dy*0.002`）在 40px/格 下只有 1.057。
- 单向改判（zoom→pan）保留：触摸板第一格可能又大又整，第二格小值揪出来。

**测试**：T30 重写，22→ 现在 40 余条：40/53/80/120/160/200/240 全须 zoom 且倍率 1.149；
1/3/7/13/21 与 37.5 与带 deltaX 全须 pan；还钉住「手势改判后不反悔」「行/页模式必鼠标」。

**验证**：tsc 干净 / ALL PASS / 469.9kb / smoke OK / 部署 SHA1 MATCH `85eb9c1d…`。
`tmp/wheelProbe.ts` 新增 `oneLineNotch`：真 WheelEvent 40px → ratio **1.149**（不是 1.057），
锚点误差仍是 0，其余（触摸板 14px 平移、k=1.32 时 30px 精确、捏合、从 svg 冒泡、filter）不变。

**教训**：设备参数不能当公理。凡是「某个像素值代表一格」的假设，都要问一句「这个值是谁定的、用户能不能改」。
判定只在**同一手势内**自洽（首个 |dy| 定标），就能绕开所有系统差异。

## 1.18.18 滚轮判定第三次修：150% 缩放报 66.666

用户贴出真实值：`66.66666666666667 -0 0`。**66.666 = 100 ÷ 1.5** —— 他的 Windows 显示缩放是 150%，
Chromium 把 CSS 像素按 deviceScaleFactor 除了一遍。而我 1.18.17 刚把「整数」当成鼠标判据。

**三次同一个教训**：设备参数不能当公理。
- 1.18.16：`|dy| === 100 或 120`（假定 3 行）→ 1 行/4 行 的机器滚轮变平移
- 1.18.17：`|dy| 是整数`（假定 100% 缩放）→ 150% 缩放的机器滚轮又变平移
- 1.18.18：**不再假设任何绝对值**

**最终判据**（`render/wheel.ts`）：
1. `ctrlKey` → 缩放（捏合 / Ctrl+滚轮）；`shiftKey` → 横移。优先级最高，不看 pin。
2. `pin`（设置项 `wheelMode` = auto/zoom/pan，默认 auto）非 auto 时直接照办，不猜。
3. auto：
   - 首格 `looksLikeWheel` = `|dy| ≥ 16` + `|dx| ≤ 0.5`（**不看是否整数**，150% 下就是小数）
   - 手势内自证：`|dy| / notchPx` 必须落在 **≥1 的整数** 上（容差 0.03）。鼠标 66.67 → 133.33 比值精确 2；
     触摸板 40 → 43 比值 1.075 → 改判平移。这条替代了所有像素假设。
   - 改判必须**直接置 pan**，不能再问一次 `looksLikeWheel`（触摸板快滑单格也过阈值，问了就弹回 zoom）。
4. 倍率按格：`notchPx` 取手势首值（夹 16~400），一格恒 2^0.2 = 1.149，与 DPI / 行数无关。

已知取舍写进测试：触摸板快滑第一格（21px）会先缩放一次，第二格自愈成平移。

**设置项**：`ObmindSettings.wheelMode` + 设置面板「滚轮操作」三档（带描述跟随）。
`MindmapView.onWheel` 每次同步 `normalizeWheelPin(settings.wheelMode)` —— 改完设置立刻生效，不用重载。
理由：形状判据永远只能覆盖大多数机器，必须留一个「别猜了」的出口。

**验证**：tsc 干净 / ALL PASS（T30 现在 50 余条：三种真实一格 40/66.667/26.667 全须 zoom 且 1.149；
触摸板 1/3/7/11/13 全须 pan；同手势 66.67→133.33 须保持 zoom 且 factor=2^-0.4；pin 三档 + Ctrl/Shift 优先级 + 收敛）。
473.0kb / smoke OK / 部署 SHA1 MATCH `c138bcc1…`。
`tmp/wheelProbe.ts` 改成 `notchShapes` 数组（40 / 66.667 / 26.667）：三档 ratio 全 **1.149**、`pivotErr` 全 **0**。
